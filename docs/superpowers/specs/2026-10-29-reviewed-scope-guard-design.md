# Reviewed question scopes

A signed, source-true reply is not necessarily an answer to the question. The strict catalog path currently returns a selected fact without an independent evidence-review pass. Repair the eligibility boundary, retaining whole replies, source fingerprints, exact evidence, privacy, version restrictions and the short-answer constraints.

Use a required v2 schema. Source authority is typed and bound to source-v2 identity. A reviewed answer carries a digest-bound scope definition (stable key, product-control or vendor-fundamental category, AND-of-OR exact approved phrase prerequisites, forbidden phrases) plus per-answer supported question forms. Definitions for the same scope key must be byte-equivalent; forms may differ by answer.

Derive a requirement locally from the complete current question. Every independent question form must be recognized and supported by the selected unit. Resolve only one reviewed scope key; zero, conflicting or multiple scope keys fail closed. Negation without an explicit reviewed negative route and quoted interrogative/instruction text fail closed. Match normalized complete words, never substrings. Phrase routing is a prerequisite, not a semantic-completeness proof: the selector must still reject a related, incomplete or differently conditioned reply. Mixed-authority/multiple-scope questions remain explicitly unresolved until a reviewed complete route exists.

Apply eligibility during candidate generation and recompute it against the canonical snapshot when accepting a returned ID. Product controls require product-help evidence; vendor fundamentals require vendor-reference evidence. Unrelated product facts must not become eligible merely because their provider is right. Do not trust the caller's candidate array or model-supplied scope.

The v2 envelope/payload, typed source authority, scope definition and supported forms are required. Reject v1 and missing fields; never infer or auto-upgrade scope. The existing required-library marker must prevent invalid/old libraries from restoring unreviewed generation after reopen. Keep old bytes for rollback.

Synthetic public fixtures cover wrong authority, wrong product scope, valid controls/fundamentals, compound forms, ambiguity/negation/quotes, duplicate definitions, changed metadata/digests and v1 persistence rejection. Private data, real question sets, libraries and keys stay outside the repository. Full real-question/unseen/native accuracy, readability, first-card timing, reports/save/reopen and independent critic remain the acceptance gate.

## Live profile changes

Freeze profile ID and general-knowledge policy before asynchronous retrieval. Verify current identity, policy and (for strict requests) catalog revision before sending a request, after the provider returns, and after optional same-issue matching. If they changed, discard the old result and requeue the same transcript under the current policy; this includes provider-error paths. Ordinary same-policy provider errors keep their existing behavior.

Plan resolution by card ID, preserving first-unhandled-card behavior for repeated titles. Do not commit resolution, mood, coaching, answer identities, cards or callbacks until the final active/cancellation/policy check. Controlled provider and matcher tests cover stale output, premature resolution/mood, callbacks, requeue, error branches and unchanged-profile controls. These remain component evidence; source review and tests never replace real question/native acceptance.
