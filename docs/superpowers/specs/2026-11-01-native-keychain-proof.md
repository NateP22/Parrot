# Native QA credential-persistence proof

The approved end-to-end plan requires a harmless credential to survive a real process restart in the supported QA service before real-provider setup. Existing regressions replace Security APIs and fake persistence in JSON, so they do not prove this requirement.

Implement one QA-only three-process probe using the actual APIKeyStore and installed signed app. This closes only that persistence component; normal API-key entry, provider authentication, real-key restart/update behavior, audio, answers and final native qualification remain separate.

Approach: preserve production queries, Keychain backend and ACLs. Add an uncached metadata-status query and make deletion report success. Reject production identity, wrong service, session-only credentials, non-setup mode, malformed or extra arguments. Use a canonical UUID nonce to derive a disposable non-provider account and a public fixture. No caller-supplied account/value/path, credential values in logs, network, audio, model or persistent meeting store.

Before any Keychain operation, the probe process calls the macOS legacy-Keychain UI-disallow API and independently reads back disallowed state. If either fails, make zero item calls. Every probe item query/add also supplies a fresh LAContext with interactionNotAllowed=true; this does not evaluate authentication or reuse an authenticated context. Keep it in the query, never the attributes-to-update. Existing normal calls default to allowInteraction=true and their query dictionaries remain unchanged. Do not migrate to the Data Protection Keychain merely to test a different backend. Apple TN3137 distinguishes the backends; sandbox entitlement alone does not select Data Protection. Deprecated APIs require a current native check; no claim of success follows headers alone.

Phase write: metadata for only the derived account must return item-not-found; all other statuses abort without save/delete. Production save uses replaceExisting=false for an atomic SecItemAdd, so a collision after the metadata check still cannot overwrite. Phase verify-cleanup: another process loads that exact account through production load, requires an exact fixture match, and calls production delete. Mismatch/unavailable refuses deletion. Phase absent: a third process performs an uncached metadata query and requires actual item-not-found. Cached nil never proves cleanup. Use bounded timeouts, exact phase outcomes and distinct exited PIDs. Reports encode status explicitly, including null, for the strict Python contract. A failed cleanup retains the nonce for a scoped retry rather than broad deletion.

The runner requires expected binary SHA256/source commit and exact version1 QA metadata, and rechecks signed identity around each phase. An exclusive0600 journal outside /tmp records the nonce and child PID before/after each launch; a lock prevents concurrent runs. Sync the journal file and directory after atomic installation, and sync history content/directory before rollover. Sync failure prevents native launch. Pending runs refuse a replacement nonce. A fully correlated definitive write collision (metadata success or atomic-add duplicate) is terminal refused, never cleanup-owned, and --recover refuses it; normal later runs may archive this refusal. Other uncertain failures retain the pending nonce. Explicit --recover uses only that same artifact/nonce and verify-cleanup/absence, never asserts persistence. Reject a possibly live prior child on the same boot; a different boot establishes that the old process cannot remain. Output/deadlines are bounded and the runner kills/reaps only its own child. Never persist raw stderr, foreign stage text or fixture values.

Tests: watch the existing setup admission reject a valid new probe (RED); then add the minimal strict admission and policy. Extend hermetic credential tests for uncached metadata/error distinctions and deletion result. Test argument/identity/session/UI-refusal/collision/mismatch/cleanup-failure behavior with all Security calls shadowed and link verification. Those are component tests only. Build on the authorized Mac CI; run the three actual Security phases from the signed artifact, and independently repeat on this Mac after verified isolated installation.

Source authority: approved full end-to-end plan Task2 (local QA record; not copied to public source); current APIKeyStore in AnalysisProvider.swift; QASetupLaunch.swift. Apple Security headers SecKeychain.h634–650 and SecItem.h1018–1036 and Apple documentation on SecKeychainSet/GetUserInteractionAllowed. No new permission or original credential access is introduced.
